# Architecture

A hand-written static site. No build step, no framework, nothing to install —
open `index.html` in a browser and it works. Deploy by copying the folder. The
one third-party script, StPageFlip, is vendored rather than fetched from a CDN.

### Stylesheet order

Every page loads, in this order: `tokens` → `base` → `components` → `layout` →
its own page sheet. Later sheets may override earlier ones; the reverse never
happens, so cascade order is the only precedence rule you need to remember.

`article.html` loads `blog.css` before `article.css`, because it reuses
`.post-meta`.

## Bilingual content — EN / RU

Both languages ship in the markup. The `<html lang>` attribute decides which set
is painted:

```css
html[lang="en"] [data-lang="ru"],
html[lang="ru"] [data-lang="en"] { display: none !important; }
```

```html
<span data-lang="en">Reserve</span><span data-lang="ru">Бронь</span>
```

Consequences worth knowing:

- **The page is correct with JavaScript off.** It renders English.
- The choice is stored in `localStorage` under `silk.lang` and applied on the
  next page load by `site.js`. Storage failures (private mode) fall back to
  English rather than throwing.
- Text generated by JavaScript — gallery captions, journal rows — cannot use
  `data-lang`. Those scripts read
  `document.documentElement.lang` and repaint on the `silk:langchange` event
  that `site.js` dispatches.
- Both languages are in the DOM, so search engines see both. If that ever
  becomes a problem, split into `/en/` and `/ru/` trees.

## JavaScript

Plain ES5-flavoured scripts in IIFEs, no modules, no bundler. Each one begins by
looking for the element it drives and returns early if it is not on the page, so
including a script on the wrong page is harmless.

`site.js` is the only file every page loads. It handles three things: language,
mobile navigation, and motion.

### Motion

**Reveal.** `site.js` tags elements below the fold with `.reveal` (plus a
`--heading`, `--line` or `--media` variant) from a selector list,
`AUTO_REVEAL`, so new sections pick up motion without markup changes. A
hand-placed `.reveal` still works. One observer releases them; elements that
arrive together cascade via `--reveal-delay`. Once landed, the reveal classes
are removed so the element's own hover transitions work again.

Two things an `IntersectionObserver` cannot see: an element clipped to nothing,
and one scaled to zero. So `--media` clips the image rather than its frame,
and `--line` is watched through its parent.

Scripts that paint their own lists call `window.SILK.reveal(nodes, variant,
true)` after each paint — see `gallery.js` and `blog.js`.

**Parallax.** The `PARALLAX` table in `site.js` maps selectors to a speed and
a limit. It sets `--py` on each layer; CSS applies it with the `translate`
property. Reveals also use `translate`, animations use `transform` — the
table never targets a revealed element, so the three do not collide.

**Scroll state.** `html.is-scrolled` and `html.nav-tucked` drive the nav; the
article also gets a reading-progress rule via `--read`.

All hiding is gated on the `js` class that an inline script in `<head>` adds,
so **content is never invisible when scripting is off**, and
`prefers-reduced-motion` switches every part of this off.

### The reservation form

The booking panel (`.booking`, styled in `components.css`) is one markup block
shared by `index.html` and `contacts.html`; it takes the teal variant on its
own when it sits in a `.ground--teal` band. Four numbered steps: day, time,
guests, details.

- **Time and guests are plain radios** in the markup, so they work without
  script. The service tabs (breakfast / lunch / dinner / late) show one set of
  times with CSS `:has()`; browsers without it get every time at once.
- **`booking.js` builds the day strip** — the next seven days plus a
  "More dates" cell that opens the native picker — because only script knows
  today's date. Without it the day falls back to a native date field. "Today"
  and "passed" are Bali time (`Asia/Makassar`), not the visitor's clock: on
  the current day, times less than 30 minutes away are disabled.
- It also reads the choice back on the ticket line, validates in place (inline
  messages, no browser bubbles), and swaps in the sent state. Its generated
  text repaints on `silk:langchange`.
- **Set an `action` attribute and the script steps aside** once the form is
  valid, letting the browser post normally. See
  [development.md](development.md#wiring-the-reservation-form).

Fields posted: `date` (ISO), `service`, `time`, `guests`, `name`, `phone`,
`note`.

### The menu book

The homepage menu preview is a bound book: leather covers, endpapers, and one
page per course. Every page is in the markup in both languages, so a change to
`menu.html` (a dish, a price, a course title) must be copied into the book by
hand. The photograph sits low on right-hand pages (`.book__paper--low`) so that
each spread reads on a diagonal.

- **`menu-viewer.js` only binds the pages.** It hands them to StPageFlip, which
  sizes them to the column, draws the curl, and handles drag, tap and swipe.
  Page contents are sized in `cqi`, so a page scales like a print.
- **Closed, the book slides to the middle** of its column (`data-book-at` =
  `front` / `back`); the slide runs for `--dur-page`, which the script mirrors
  as `TURN`.
- **Below two 220px pages side by side, it shows one page at a time.**
- **Without the library** — scripting off, or the file missing — the pages sit
  in a row you scroll sideways, and the controls stay hidden.
- Reduced motion turns pages instantly from the buttons and keys, and drops
  the hover curl. Dragging still works; the reader is moving it.

## Shared chrome

The navigation and footer are duplicated in all nine HTML files — the cost of
having no build step. **If you change one, change all nine.** They are marked by
`<header class="nav">` and `<footer class="footer">` and are byte-identical
apart from the `aria-current="page"` marker on the active nav link.

A `grep` to find them all:

```bash
grep -l 'class="nav__brand"' *.html
```

## Accessibility notes

- Every page opens with a skip link to `#main`.
- The mobile nav toggle is a real `<button>` with `aria-expanded` and
  `aria-controls`; Escape closes it and returns focus.
- Filter chips use `aria-pressed`, not a class, as the source of truth — the CSS
  selector is `.filter[aria-pressed="true"]`.
- The lightbox traps nothing, but it sets `aria-modal`, moves focus on open,
  restores it on close, and closes on Escape.
- Focus is visible everywhere via `:focus-visible` in jade (`--jade`).
- Decorative pattern layers and marks carry `aria-hidden="true"`.

## Browser support

Modern evergreen browsers. The site uses CSS custom properties, `clamp()`,
`aspect-ratio`, `color-mix()`, grid and `:focus-visible`. `color-mix()` is used
only for the button inset rules, which degrade to no border rather than to
broken layout.
